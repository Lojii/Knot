## 功能描述

请求详情面板位于 List Tab 的下半区域，在用户选中某条流量后展示该请求的完整信息。共包含 7 个 Tab：Headers、Body、Query、Cookies、Timing、Connection、Certificate。面板顶部还提供 "Edit & Resend" 和 "Copy as cURL" 快捷操作。

## 用户操作流程

1. 在 FlowTable 中点击某行流量 → 选中该流量
2. DetailController 加载详情 (loadDetail) 和 body (loadBodies)
3. 详情面板显示加载中状态 → 加载完成后展示 7 个 Tab
4. 点击各 Tab 查看不同维度的信息
5. 点击 "Copy as cURL" → cURL 命令复制到剪贴板
6. 点击 "Edit & Resend" → 跳转到 Compose 页面并预填充

## 界面设计

### 顶部工具栏 (38px)
- 右对齐: "Edit & Resend" 按钮 (editNote icon) + "Copy as cURL" 按钮 (copy icon)

### Tab 栏
- 7 个 Tab: Headers / Body / Query / Cookies / Timing / Connection / Certificate
- isScrollable, tabAlignment: start, 高度 28px

### Headers Tab
- Request Headers 标题 + KeyValueTable（等宽字体，键名粗体）
- Response Headers 标题 + KeyValueTable
- 从 `detail.raw.metadata.requestHeaders` / `responseHeaders` 解析
- 格式: `[[name, value], ...]`

### Body Tab
- Request Body 标题 + BodyViewer 组件（带 Pretty/Raw/Hex 模式切换）
- Response Body 标题 + BodyViewer 组件
- 从 API getPayload(preview: true) 加载
- BodyViewer 根据 Content-Type 自动检测展示模式

### Query Tab
- 从 flow detail 的 searchKey2 (URI) 中解析 query parameters
- 使用 `Uri.tryParse()` + `queryParametersAll` 提取
- KeyValueTable 展示
- 无参数时显示 "No query parameters"

### Cookies Tab
- Request Cookies: 从请求头的 Cookie 字段解析（分号分隔）
- Response Set-Cookie: 从响应头的 Set-Cookie 字段解析
- 均使用 KeyValueTable 展示
- 无 cookie 时显示 "No cookies"

### Timing Tab
- 6 个时间点: Connect / Connected / TLS Done / Request End / Response Start / Response End
- 每行: 120px 事件名 + 等宽字体显示相对于 startedAt 的毫秒偏移
- 数据来自 FlowDetail 的 connectAt / connectedAt / tlsDoneAt / reqEndAt / rspStartAt
- 缺失字段显示 "-"

### Connection Tab
- KeyValueTable 展示:
  - Source: {srcIp}:{srcPort}
  - Destination: {dstIp}:{dstPort}
  - State: 连接状态
  - TLS Version（如有）
  - Cipher（如有）
  - SNI（如有）
- 无连接信息时显示 "No connection info"

### Certificate Tab
- TLS 证书信息展示:
  - TLS Version
  - Cipher Suite
  - SNI
  - Certificate Chain Ref（如有）
- 无 TLS 信息时显示 "No certificate information"

## 技术实现

### 前端（Flutter）
- **FlowDetailPanel**: StatelessWidget，内嵌 DefaultTabController(length: 7)
- 7 个 Tab 对应 7 个私有 StatelessWidget
- 所有 Tab 通过 Obx 监听 DetailController 数据变化
- KeyValueTable: Table 布局，第一列 IntrinsicColumnWidth，第二列 FlexColumnWidth
- CurlExport.fromFlowDetail() 构建 cURL 命令

### 后端（Swift/KnotWebService）
- **GET /api/tasks/{taskId}/flows/{flowId}**: 返回详情 JSON
- **GET /api/tasks/{taskId}/flows/{flowId}/request?preview=true**: 请求 body
- **GET /api/tasks/{taskId}/flows/{flowId}/response?preview=true**: 响应 body

## 边界条件与异常处理

- 未选中流量时显示 "Select a request to view details"
- 详情加载中显示 CircularProgressIndicator
- body 加载中显示 CircularProgressIndicator
- headers 为空时显示 "No headers available"
- body 加载失败时清空为空字符串

## Proxyman 参考

### 功能对标

Proxyman 的 Flow Content 面板，即选中请求后右侧/下方显示的详情区域。对应 Request Viewer 和 Response Viewer。

### Proxyman 界面布局描述

Proxyman 的 Flow Content 面板分为上方 Request 和下方 Response 两个区域（可水平/垂直切换）：

**Request 区域 Tabs：**
- **Header**: 请求头 key-value 表格，支持搜索过滤
- **Cookies**: 请求中的 Cookie 字段解析为表格
- **Auth**: Authorization 头自动解析（Bearer Token、Basic Auth 等）
- **Body**: 自动格式化显示（JSON Tree View 带 JSONPath 搜索、Hex、Raw、Protobuf、MessagePack）
- **Query**: URL 查询参数表格展示
- **Raw**: 完整 HTTP 报文（请求行+头+空行+body）
- **Multipart/form-data**: 表单上传文件解析

**Response 区域 Tabs：**
- **Header**: 响应头 key-value 表格
- **Set-Cookie**: 响应 Set-Cookie 字段完整解析（包括 expires/path/domain/secure/httponly 属性）
- **Body**: 同请求区域 Body（JSON Tree View / Hex / Raw / Protobuf）
- **Raw**: 完整 HTTP 响应报文

**Body Viewer 功能：**
- Tree View: JSON 树形展示，支持 JSONPath 搜索、节点折叠/展开
- Hex: 十六进制转储
- Export: 导出 body 到文件
- Open With: 用外部编辑器打开

### 参考截图

| 截图 | 说明 |
|------|------|
| （文字描述）Proxyman Request Viewer | 上方请求区域包含 Header/Cookies/Auth/Body/Query/Raw/Multipart 多个 Tab，Body Tab 内有 Tree View（JSON 树形结构，支持搜索和折叠）、Hex、Raw 子 Tab。Header Tab 以表格形式展示键值对 |
| （文字描述）Proxyman Response Viewer | 下方响应区域包含 Header/Set-Cookie/Body/Raw Tab。Body Tab 的 JSON Tree View 左侧为树形结构，右侧为选中节点的值预览 |

### 布局优缺点分析

**优点：**
- Tab 分类非常细致，Auth、Set-Cookie、Multipart 都有独立 Tab
- JSON Tree View 支持 JSONPath 搜索，查找嵌套数据非常高效
- Body Viewer 支持多种格式（Protobuf、MessagePack 等）
- 可导出 body 到文件或用外部编辑器打开
- Set-Cookie 完整解析所有属性

**缺点：**
- Tab 数量较多，需要滚动查找
- Tree View 在超大 JSON 时可能性能问题

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| Tab 数量 | Request 7个 + Response 4个 | 统一 7 个 Tab |
| Auth 解析 | 独立 Auth Tab | 无（需在 Headers 中查找） |
| Set-Cookie | 独立 Tab + 属性解析 | Cookies Tab 但不解析属性 |
| Body 格式 | Tree View / Hex / Raw / Protobuf / MessagePack | Pretty / Raw / Hex |
| JSON 搜索 | JSONPath 搜索 | 无 |
| Multipart | 独立 Tab 解析 | 无 |
| Raw 报文 | 完整 HTTP 报文 | 无独立 Raw Tab |
| 外部编辑器 | 支持 Open With | 不支持 |
| Timing | 无独立 Tab（信息在其他位置） | 独立 Timing Tab |
| Connection | 无独立 Tab | 独立 Connection Tab |
| Certificate | 无独立 Tab | 独立 Certificate Tab |

### Knot 中尚未实现的 Proxyman 功能

- **Auth Tab**: 自动解析 Authorization 头（Bearer/Basic/Digest 等）
- **JSON Tree View**: 可折叠/展开的 JSON 树形结构浏览器
- **JSONPath 搜索**: 在 JSON body 中按路径搜索
- **Protobuf 解码**: 支持 .desc 文件解码 Protobuf body
- **MessagePack 解码**: 支持 MessagePack 格式解码
- **Multipart 解析**: 独立 Tab 解析 multipart/form-data 上传
- **Raw HTTP 报文**: 显示完整的请求行+头+空行+body 原始报文
- **Body 导出**: 将 body 导出为文件
- **Set-Cookie 属性解析**: 解析 expires/path/domain/secure/httponly
