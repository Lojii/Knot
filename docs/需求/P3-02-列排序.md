## 功能描述

流量列表表头支持点击排序功能。用户可以通过点击列标题对流量进行升序/降序排列，三次点击循环：升序 → 降序 → 取消排序。支持 6 个排序维度：Method、Host、Path、Status、Size、Time。

## 用户操作流程

1. 点击 FlowTable 的某个列标题（如 "Status"）
2. 第一次点击 → 升序排列，标题旁显示 ▲
3. 再次点击同列 → 降序排列，标题旁显示 ▼
4. 第三次点击 → 取消排序，恢复原始顺序
5. 点击不同列 → 切换到新列的升序排列

## 界面设计

### 表头
- 各列标题均为 GestureDetector，可点击
- 当前排序列旁显示排序箭头: ▲（升序）或 ▼（降序）
- 箭头字体 10px（fontSizeXS），粗体

### 排序列定义
| 列名 | 枚举值 | 比较逻辑 |
|------|--------|---------|
| Method | _SortColumn.method | 字母序比较 method |
| Host | _SortColumn.host | 字母序比较 host |
| Path | _SortColumn.path | 字母序比较 uri |
| Status | _SortColumn.status | 字母序比较 statusCode |
| Size | _SortColumn.size | 数值比较 downloadBytes |
| Time | _SortColumn.time | 数值比较 durationMs (null 视为 0) |

## 技术实现

### 前端（Flutter）
- **_FlowTableState**: 管理 `_sortColumn` (nullable) 和 `_sortAscending` (bool)
- `_onSortTap()`: 三态切换逻辑
  - 不同列 → 设为该列升序
  - 同列+升序 → 切换为降序
  - 同列+降序 → 重置为无排序
- `_applySorting()`: 对 items 列表创建副本后 sort，不修改原始数据
- `_sortableHeader()`: 构建可点击的表头单元格，支持固定宽度或 flex 弹性

### 后端（Swift/KnotWebService）
- 排序为纯前端操作，不涉及后端

## 边界条件与异常处理

- 无数据时仍显示表头（可点击但无效果）
- durationMs 为 null 时排序中视为 0
- statusCode 为字符串类型，按字母序（非数值序）比较

## Proxyman 参考

### 功能对标

Proxyman 中间 Flow List（请求列表表格）的列排序功能。

### Proxyman 界面布局描述

Proxyman 的请求列表表格排序：
- **表头点击排序**：点击任意列头即可排序，再次点击切换升/降序
- **排序箭头指示**：当前排序列的表头显示向上/向下箭头
- **可排序列**：序号（#）、Method、Name（路径）、Status、Size、Time、Content-Type
- **默认排序**：按请求到达时间顺序（序号列）
- **表头样式**：macOS 原生 NSTableView 表头，灰色背景，点击时有按下反馈
- 使用 macOS 原生 NSTableView 控件，排序性能优秀，支持大数据量

### 布局优缺点分析

**优点：**
- 使用原生 NSTableView，排序性能优异，万级请求无卡顿
- 排序交互符合 macOS 标准表格操作习惯
- 列宽可自由调整，拖拽列头边缘即可

**缺点：**
- 不支持多列组合排序
- 排序状态不够明显（仅小三角箭头）

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| 排序控件 | 原生 NSTableView | Flutter 自定义实现 |
| 排序性能 | 原生优化，大数据量流畅 | 每次 Obx rebuild 执行 sort |
| 三态循环 | 两态（升序/降序） | 三态（升序/降序/取消） |
| 列宽调整 | 支持拖拽调整 | 固定宽度 |
| 排序指示 | macOS 原生三角箭头 | 文字 ▲/▼ |

### Knot 中尚未实现的 Proxyman 功能

- **列宽调整**: Proxyman 支持拖拽调整列宽
- **自定义列显示**: Proxyman 可选择显示/隐藏哪些列
- **高性能排序**: 原生 NSTableView 排序性能远优于 Flutter 重建
