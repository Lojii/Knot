## 功能描述

历史任务管理面板提供对所有抓包任务的浏览、搜索、切换、删除和批量操作能力。用户可以查看过去的抓包会话，快速切换到某个历史任务查看其流量数据，也可以清理不需要的历史记录。

## 用户操作流程

### 普通模式
1. 点击 GlobalBar 的 History 按钮 → 进入历史面板
2. 列表自动加载所有历史任务
3. 搜索框输入关键词 → 按任务名或 ID 实时过滤
4. 点击某个任务 → 切换到该任务并回到抓包页面
5. 右键任务 → 弹出上下文菜单（打开 / 删除）
6. 点击行末 "..." 按钮 → 同上下文菜单

### 编辑模式
1. 点击 "编辑" 按钮 → 进入编辑模式
2. 每行出现 Checkbox，支持多选
3. 工具栏显示: 全选 Checkbox + 已选计数 + "完成" 按钮 + "删除" 按钮
4. 勾选要删除的任务 → 点击 "删除 (N)" → 确认对话框 → 批量删除
5. 点击 "完成" 退出编辑模式

├──────────────────────────────────────────────────┤
│ ┌ TaskRow ────────────────────────────────────┐  │
│ │ ● Task 1  2026-03-20 14:30  42 flows ↑1.2K ↓45.3M [46.5M] ...│
│ ├─────────────────────────────────────────────┤  │

│ └─────────────────────────────────────────────┘  │

### 普通模式工具栏
- "Capture History" 标题 + 任务总数 + "编辑" 按钮 + 搜索框 (200px)

### 编辑模式工具栏
- 全选 Checkbox + "已选 N / M" + "完成" 按钮 + 右侧红色 "删除 (N)" 按钮

### 任务行 (_TaskRow)
- 左侧: 编辑模式下显示 Checkbox；普通模式下当前任务显示绿色圆点
- 任务名 (120px, 粗体高亮当前任务)
- 创建时间 (140px, 格式 YYYY-MM-DD HH:MM)
- 流量数 (80px, "N flows")
- 上行 (80px, ↑ 图标 + 字节数)
- 下行 (80px, ↓ 图标 + 字节数)
- 总流量 badge（圆角背景）
- "..." 按钮（非编辑模式）

### 上下文菜单
- "打开": 切换到该任务 + 返回抓包页面
- "删除": 确认对话框后删除

### 删除确认对话框
- 标题: "删除确认"
- 内容: "确定删除 Task {id} 及其所有数据？" 或 "确定删除 N 个任务及其所有数据？"
- 按钮: "取消"(灰) + "删除"(红)

### 删除进行中遮罩
- 半透明黑色遮罩 + 居中卡片 + CircularProgressIndicator + "正在删除..."

## 技术实现

### 前端（Flutter）
- **HistoryPanel**: StatefulWidget，管理搜索、编辑模式、选中集合、删除状态
- 搜索过滤: 本地 toLowerCase contains 匹配任务名和 ID
- 选中管理: `_selectedIds: Set<int>`
- 全选/取消: 仅操作当前可见（过滤后）的任务
- 编辑/删除状态通过 `setState` 管理（非 GetX）

### 后端（Swift/KnotWebService）
- **GET /api/tasks**: 返回所有任务列表
- **DELETE /api/tasks/{taskId}**: 删除单个任务及其数据
- **POST /api/tasks/batch-delete**: body `{"ids": [1,2,3]}`，批量删除

## 边界条件与异常处理

- 无历史任务时显示 "No capture history"
- 搜索无结果时同上
- 删除失败时 SnackBar 提示 "删除失败: {error}" 或 "批量删除失败: {error}"
- 删除进行中禁止其他操作（遮罩层）
- 加载中显示 CircularProgressIndicator（非删除期间）

## Proxyman 参考

### 功能对标

Proxyman 的 Session 管理功能，位于 File 菜单下的 Session 相关操作。

### Proxyman 界面布局描述

Proxyman 的会话（Session）管理方式：
- **自动会话管理**：每次启动自动创建新 Session，历史 Session 通过 File → Open Recent 访问
- **Session 文件保存**：File → Save（⌘S）将当前会话保存为 .proxyman 文件
- **Session 导入**：File → Open（⌘O）打开已保存的 .proxyman 文件或 Charles Session (.chls)
- **没有独立的历史任务管理面板**：会话管理依赖文件系统，而非应用内的列表管理
- **新建 Session**：File → New Window（⌘N）或 New Tab
- Proxyman 的理念是将会话视为文件，用 macOS 的文件管理器来管理

### 参考截图

| 截图 | 说明 |
|------|------|
| （文字描述）Proxyman File 菜单 | 包含 New Window、Open、Open Recent（子菜单列出最近的 Session 文件）、Save、Save As、Export 等标准文件操作。Session 文件使用 .proxyman 扩展名 |

### 布局优缺点分析

**优点：**
- 遵循 macOS 文件管理范式，用户熟悉
- 支持多窗口/多 Tab 同时查看不同 Session
- 可以在 Finder 中组织和管理 Session 文件
- 支持导入 Charles Session

**缺点：**
- 没有统一的历史会话列表视图
- 无法在应用内搜索历史会话
- 文件管理方式对于频繁创建 Session 的用户不够便捷
- 无法看到历史 Session 的统计信息（流量数、大小等）

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| 会话管理方式 | 基于文件系统(.proxyman) | 应用内列表管理 |
| 历史浏览 | File → Open Recent | 独立 History 面板 |
| 批量操作 | 文件系统级别操作 | 应用内多选+批量删除 |
| 搜索 | Finder 搜索 | 应用内实时搜索过滤 |
| 统计信息 | 需打开文件才能查看 | 列表直接显示流量数/大小 |
| 多会话切换 | 多窗口/多 Tab | 单任务切换 |

### Knot 中尚未实现的 Proxyman 功能

- **Session 文件导出/导入**: Proxyman 支持将会话保存为文件，方便分享和归档
- **多窗口/多 Tab**: Proxyman 可同时打开多个 Session 窗口
- **导入 Charles Session**: Proxyman 可导入 .chls 文件
- **任务重命名**: Proxyman 支持 Save As 重命名 Session
