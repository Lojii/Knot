## 功能描述

Dashboard Tab 提供当前抓包任务的可视化概览，包括协议分布饼图、状态码统计、系统资源指标（内存/CPU/线程/连接/运行时长）和流量汇总。数据结合 REST API 加载的静态统计与 WebSocket 推送的实时指标。

## 用户操作流程

1. 在 ContentPanel 中点击 "Dashboard" Tab
2. 自动通过 DashboardController.loadStats() 从 API 加载当前任务的统计数据
3. 实时指标通过 WebSocket metrics 消息持续更新
4. 面板以卡片网格形式展示各类指标

## 界面设计

### 布局结构
```
┌──────────────────────────────────────────┐
│ Row 1:                                   │
│ ┌─Protocol Distribution─┐ ┌─Status Codes─┐ │
│ │     🥧 饼图           │ │ Completed: 42│ │
│ │  HTTP:12 HTTPS:28    │ │ Failed: 3    │ │
│ └───────────────────────┘ └──────────────┘ │
├──────────────────────────────────────────┤
│ Row 2: 系统指标卡片                       │
│ ┌Memory┐ ┌─CPU──┐ ┌Threads┐ ┌Conn┐ ┌Uptime┐ │
│ │128 MB│ │2.5% │ │  12  │ │ 8  │ │ 340s │ │
│ └──────┘ └─────┘ └──────┘ └────┘ └──────┘ │
├──────────────────────────────────────────┤
│ Row 3: Traffic                           │
│      Upload: 1.2 MB    Download: 45.3 MB │
│      Total: 46.5 MB                      │
└──────────────────────────────────────────┘
```

### Row 1: 协议分布 + 状态码
- 两列等宽，使用圆角卡片容器
- **Protocol Distribution**: fl_chart PieChart，按协议着色（HTTP=蓝, HTTPS=绿, H2=橙等），每段显示协议名+数量，中心空洞半径20
- **Status Codes**: 文本列表，每行显示状态名称 + 右对齐数量

### Row 2: 系统指标
- 5 个等宽指标卡片，纵向排列: 图标 + 数值 + 标签
- Memory (memory icon): RSS 内存占用 MB
- CPU (speed icon): 使用率百分比
- Threads (account_tree icon): 线程数
- Connections (cable icon): 连接池总数
- Uptime (timer icon): 运行时长秒数

### Row 3: 流量汇总
- Upload / Download / Total 三列，大号粗体数字
- 自动格式化: B → KB → MB

## 技术实现

### 前端（Flutter）
- **DashboardTab**: StatefulWidget，initState 时触发 loadStats
- 使用 fl_chart 的 PieChart 绘制协议分布饼图
- 所有数据通过 Obx 响应式更新
- DashboardController 管理:
  - `protocols`: Map<String, int>（从 REST API 加载）
  - `statuses`: Map<String, int>
  - `totalUpload` / `totalDownload`: 总字节数
  - `rssMB` / `cpuPercent` / `threadCount` / `poolTotal` / `uptimeSeconds`: 实时指标
  - `trafficHistory`: 最近 60 个流量数据点（时间+字节）

### 后端（Swift/KnotWebService）
- **REST API**: GET /api/tasks/{taskId}/flows/stats 返回 protocols/statuses/totalUploadBytes/totalDownloadBytes
- **WebSocket metrics 消息**: 包含 memory.rss_mb / cpu.usage_percent / cpu.thread_count / connections.pool_total / totals.uptime_s

## 边界条件与异常处理

- 无统计数据时饼图/列表显示 "No data"
- metrics 消息字段可能缺失，用 ?? 0 兜底
- trafficHistory 最多保留 60 个点，超出移除最旧的

## Proxyman 参考

### 功能对标

Proxyman 没有独立的 Dashboard/看板视图。统计信息分散在状态栏和流量列表中。

### Proxyman 界面布局描述

Proxyman 的统计相关信息分布：
- **底部状态栏**：显示当前请求总数、过滤后的请求数
- **流量列表**：可通过列排序（如按 Size 排序）间接获取流量分布信息
- **没有独立的图表/仪表盘页面**：不提供协议分布饼图、系统资源监控、流量曲线等可视化面板
- Proxyman 更关注单个请求的调试而非整体统计概览

### 布局优缺点分析

**优点：**
- 界面简洁，不会分散用户注意力
- 请求计数实时更新

**缺点：**
- 缺少系统资源监控（内存、CPU、连接数等）
- 缺少协议/状态码分布的可视化
- 缺少流量趋势图表
- 无法快速了解抓包会话的整体情况

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| Dashboard 面板 | 无 | 有独立的 Dashboard Tab |
| 协议分布图 | 无 | 饼图展示 |
| 状态码统计 | 无 | 列表展示 |
| 系统指标监控 | 无 | Memory/CPU/Threads/Connections/Uptime |
| 流量汇总 | 无 | Upload/Download/Total |

### Knot 中尚未实现的 Proxyman 功能

- 此功能为 Knot 特色功能，Proxyman 未提供对应面板。Knot 在此处具有差异化优势。
