## 功能描述

Map Remote（远程映射）功能允许用户配置 URL 重定向规则：当请求匹配指定模式时，将其重定向到不同的 scheme/host/port/path。这在 API 调试中非常常用，例如将生产环境 API 映射到本地开发服务器。

## 用户操作流程

1. 点击 GlobalBar → Tools 菜单 → "Map Remote"
2. 进入 Map Remote 管理面板
3. 点击 "Add Rule" → 弹出规则编辑对话框
4. 输入匹配模式（如 `https://api.example.com/v1/*`）
5. 输入替换目标的各字段（scheme/host/port/path，留空表示不改变）
6. 点击 "Add" 保存规则
7. 规则列表中可以: 开关切换 (Switch) / 点击编辑 / 删除

### 空状态
- 居中图标 (alt_route, 48px) + "No Map Remote rules" + 说明文字

### 规则行 (_RuleRow)
- 左侧: Switch 开关 (40px)
- 中间:
  - 匹配模式（等宽字体, 12px，禁用时灰色）
  - 箭头图标 + 替换目标摘要（灰色, 11px）
- 右侧: 删除按钮 (delete_outline)

### 规则编辑对话框 (_MapRemoteRuleDialog)
```
┌──────────────────────────────────┐
│ Add Map Remote Rule              │
│                                  │
│ Match Pattern                    │
│ [https://api.example.com/v1/*  ] │
│                                  │
│ Replace With (empty = keep)      │
│ Scheme: [https        ]          │
│ Host:   [localhost     ]          │
│ Port: [8080] Path: [/api/v2/*]   │
│                                  │
│              [Cancel]  [Add]     │
└──────────────────────────────────┘
```
- 宽度 420px
- Match Pattern: 等宽字体输入框, autofocus
- Replace With 区域: Scheme/Host/Port/Path 四个字段，Port+Path 同行
- 编辑模式标题为 "Edit Rule"，按钮为 "Save"

### MapRemoteRule 数据结构
| 字段 | 类型 | 说明 |
|------|------|------|
| enabled | bool | 是否启用 |
| matchPattern | String | URL 匹配模式 |
| replaceScheme | String? | 替换协议（null=不变） |
| replaceHost | String? | 替换主机 |
| replacePort | int? | 替换端口 |
| replacePath | String? | 替换路径 |

- `replacementSummary`: 人类可读的替换目标描述（如 "https://localhost:8080/api/v2"），全空时显示 "(no change)"
- `copyWith()`: 支持不可变更新

## 技术实现

### 前端（Flutter）
- **MapRemotePanel**: StatelessWidget，Obx 监听 toolsCtrl.mapRemoteRules
- **_MapRemoteRuleDialog**: StatefulWidget，管理 5 个 TextEditingController
- **ToolsController**:
  - `mapRemoteRules: RxList<MapRemoteRule>`
  - addMapRemoteRule / removeMapRemoteRule / toggleMapRemoteRule / updateMapRemoteRule

### 后端（Swift/KnotWebService）
- 当前规则仅存储在前端内存中
- 需要通过 API 将规则同步到代理引擎执行实际重定向

## 边界条件与异常处理

- matchPattern 为空时不允许保存
- 所有 replace 字段留空时显示 "(no change)"
- Port 输入非数字时 int.tryParse 返回 null

## Proxyman 参考

### 功能对标

Proxyman 的 Map Remote 功能，位于 Tools → Map Remote 菜单中。

### Proxyman 界面布局描述

Proxyman 的 Map Remote 管理界面：
- **规则列表面板**：独立窗口，列表展示所有 Map Remote 规则
- **每条规则显示**：启用开关 + Match URL Pattern + Replace URL Pattern + 编辑/删除按钮
- **规则编辑对话框**：
  - **Match 区域**：URL Pattern 输入框，支持通配符（*、*.domain.com、v?.domain.com）
  - **Replace With 区域**：分段输入 Scheme / Host / Port / Path / Query，留空表示保持原值不变
- **特性**：
  - 支持 WebSocket（ws ↔ wss 协议映射）
  - 支持 GraphQL query name 匹配
  - 常见场景：localhost ↔ production、API v1 ↔ v2
  - 规则有优先级（列表顺序）
  - 可导入/导出规则配置

### 参考截图

| 截图 | 说明 |

| （文字描述）Proxyman Map Remote 规则列表 | 独立窗口，左侧列表显示所有规则，每条规则有启用复选框 + Match Pattern + Replace Pattern。右侧为选中规则的详细编辑区域。底部有 +/- 按钮增删规则 |

### 布局优缺点分析

**优点：**
- 分段替换（Scheme/Host/Port/Path/Query）设计清晰，空字段保持原值的设计直观
- 支持通配符和 GraphQL query name 匹配
- 支持 WebSocket 协议映射
- 规则可导入/导出

**缺点：**
- 规则较多时列表可能较长，缺少搜索过滤
- 通配符语法需要学习

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| 窗口 | 独立窗口 | 内嵌面板 |
| 规则持久化 | 持久化保存 | 仅内存 |
| 代理引擎集成 | 实际生效 | 仅 UI 管理（不生效） |
| 通配符 | 支持 */v? 等 | 界面支持但引擎未集成 |
| WebSocket | 支持 ws ↔ wss | 不支持 |
| GraphQL | 支持 query name 匹配 | 不支持 |
| 导入/导出 | 支持 | 不支持 |
| 规则排序 | 支持拖拽排序 | 不支持 |

### Knot 中尚未实现的 Proxyman 功能

- **WebSocket 映射**: 支持 ws ↔ wss 协议转换
- **GraphQL query name 匹配**: 按 GraphQL 操作名匹配
- **规则导入/导出**: 保存和分享规则配置
- **规则拖拽排序**: 调整规则优先级
