## 功能描述

在实时抓包页面中注册一系列键盘快捷键，让用户无需鼠标操作即可完成常用操作。使用 Flutter 的 Shortcuts + Actions 框架实现。

## 用户操作流程

| 快捷键 | 操作 | 对应 Intent |
|--------|------|-------------|
| Cmd+F | 聚焦搜索框 | FocusSearchIntent |
| Cmd+K | 清空流量列表 | ClearFlowsIntent |
| Cmd+E | 切换开始/停止抓包 | ToggleCaptureIntent |
| Escape | 取消选中流量 | DeselectFlowIntent |
| Cmd+C | 复制选中流量为 cURL | CopyAsCurlIntent |
| Cmd+R | 重放选中请求 | RepeatRequestIntent |

## 界面设计

- 无可视化 UI 元素
- 操作反馈:
  - Cmd+F: 搜索框获得焦点并显示光标
  - Cmd+K: 流量列表即时清空
  - Cmd+E: TaskController.isCapturing toggle（影响 Toolbar 按钮状态）
  - Escape: 详情面板隐藏（selectedFlow 设为 null）
  - Cmd+C: 剪贴板写入 cURL 命令
  - Cmd+R: SnackBar 显示重放结果 "{statusCode} ({elapsedMs}ms)" 或 "Repeat failed: {error}"

## 技术实现

### 前端（Flutter）
- **Shortcuts widget**: 定义 `Map<ShortcutActivator, Intent>`
  - 使用 `SingleActivator(LogicalKeyboardKey.xxx, meta: true)`
  - Escape 无 meta 修饰符
- **Actions widget**: 定义 `Map<Type, Action<Intent>>`
  - 各 Intent 对应 CallbackAction
- **Focus(autofocus: true)**: 确保页面获得焦点以接收键盘事件
- **搜索聚焦**: 通过 FocusNode.requestFocus() 实现

### Cmd+R 重放逻辑
1. 获取选中的 flow
2. 检查 detailCtrl.detail 是否已加载且为当前 flow
3. 若未加载则先 loadDetail
4. 调用 RequestSender.repeat() 发送请求
5. 异步回调显示 SnackBar

### 后端（Swift/KnotWebService）
- Cmd+R 重放请求直接由 Flutter HTTP 客户端发送（不经过代理）

## 边界条件与异常处理

- 未选中流量时 Cmd+C 和 Cmd+R 不执行操作（flow == null 早返回）
- 重放请求网络错误时 SnackBar 显示 "Repeat failed: {error}"
- context.mounted 检查防止已卸载 widget 访问 ScaffoldMessenger
- Cmd+C 生成简化 cURL（仅 method+URL，无 headers）

## Proxyman 参考

### 功能对标

Proxyman 的全局快捷键系统，分布在菜单栏各菜单项中。

### Proxyman 界面布局描述

Proxyman 作为原生 macOS 应用，快捷键通过菜单栏注册：
- **⌘⏎ (Cmd+Enter)**: Repeat 重放请求
- **⌘⇧C**: Copy as cURL
- **⌘⌥P**: 启用/禁用 SSL Proxying
- **⌘⌥N**: 启用/禁用 No Caching
- **⌘F**: 搜索/Multiple Filters
- **⌘K**: 清空请求列表
- **⌘N**: 新建窗口
- **⌘S**: 保存 Session
- **⌘O**: 打开 Session
- **⌘,**: 打开 Preferences
- **上下箭头**: 在请求列表中导航
- **Delete**: 删除选中请求
- 所有快捷键在菜单栏中显示，用户可通过菜单发现快捷键

### 参考截图

| 截图 | 说明 |
|------|------|
| （文字描述）Proxyman 菜单栏快捷键 | 菜单栏各项操作右侧显示快捷键标识，如 Edit 菜单中 "Copy as cURL ⌘⇧C"、Tools 菜单中 "Repeat ⌘⏎"。所有快捷键均遵循 macOS 标准命名规范 |

### 布局优缺点分析

**优点：**
- 通过菜单栏自然暴露快捷键，可发现性强
- 快捷键设计遵循 macOS 惯例，无冲突
- 支持上下箭头列表导航，键盘操作流畅

**缺点：**
- 不支持自定义快捷键
- 部分快捷键需记忆（如 ⌘⌥P）

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| 快捷键注册 | macOS 菜单栏 | Flutter Shortcuts + Actions |
| Copy cURL | ⌘⇧C（不冲突） | ⌘C（与系统复制冲突） |
| Repeat | ⌘⏎ | ⌘R |
| 列表导航 | 上下箭头 | 不支持 |
| 快捷键发现 | 菜单栏显示 | 无 UI 提示 |
| SSL 切换 | ⌘⌥P | 无 |
| No Caching | ⌘⌥N | 无快捷键 |

### Knot 中尚未实现的 Proxyman 功能

- **上下箭头导航**: 在请求列表中用键盘上下切换选中项
- **不冲突的快捷键设计**: ⌘⇧C 代替 ⌘C 用于 Copy cURL
- **菜单栏快捷键显示**: 通过菜单栏让用户自然发现快捷键
- **⌘⌥P SSL 切换**: 快速切换域名的 SSL Proxying
- **⌘⌥N No Caching 切换**: 快捷键切换缓存禁用
- **Delete 键删除**: 删除选中的请求
- **自定义快捷键**: 用户自定义快捷键映射
