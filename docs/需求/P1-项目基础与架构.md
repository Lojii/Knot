## 功能描述

Phase 1 建立了 Knot Flutter 应用的整体基础架构，包括项目初始化、Swift 原生包迁移、数据模型定义、API 通信层、状态管理体系、主题系统和 macOS 平台集成。这一阶段的目标是搭建完整的应用骨架，使后续功能可以快速迭代。

## 1. Flutter 项目创建 + Swift 包迁移

### 描述
项目采用 Flutter macOS 桌面应用架构，原生 Swift 代码包（KnotStorage、KnotWebService、TunnelServices）放置在 `native/` 目录下，作为本地代理引擎的核心组件。Flutter 层负责 UI 展示，Swift 层负责网络抓包、流量处理和数据存储。

### 技术细节
- **Flutter SDK**: ^3.10.4（Dart 3.x）
- **native/KnotStorage**: 数据持久化模块
- **native/KnotWebService**: 本地 HTTP API 服务端（端口 9090），为 Flutter 层提供 REST API 和 WebSocket 推送
- **native/TunnelServices**: 代理隧道核心服务（协议分发、TLS MITM、HTTP1/HTTP2 插件等）
- **依赖管理**: pubspec.yaml 使用 get (4.6.6)、http (1.2.0)、web_socket_channel (2.4.0)、multi_split_view (3.1.0)、google_fonts (6.1.0)、fl_chart (0.69.0)

## 2. Dart 数据模型

### TaskModel (`lib/models/task_model.dart`)
抓包任务模型，对应后端的一次抓包会话。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 任务唯一 ID |
| name | String | 任务名称 |
| createdAt | double | 创建时间（Unix epoch 秒） |
| startedAt | double? | 开始抓包时间 |
| stoppedAt | double? | 停止抓包时间 |
| status | int | 任务状态（0=默认） |
| flowCount | int? | 流量条数 |
| uploadBytes | int? | 上行总字节 |
| downloadBytes | int? | 下行总字节 |

### FlowSummary (`lib/models/flow_summary.dart`)
单条流量摘要，用于列表展示。

| 字段 | 类型 | 说明 |
|------|------|------|
| flowId | String | 流量唯一 ID |
| protocol | String | 协议 (HTTP/HTTPS/H2/WS) |
| host | String | 目标域名 |
| port | int | 端口 |
| startedAt | double | 开始时间 |
| endedAt | double? | 结束时间 |
| durationMs | double? | 耗时（毫秒） |
| uploadBytes | int | 上行字节 |
| downloadBytes | int | 下行字节 |
| status | int | 状态码 |
| summary | String | 摘要文本 |
| searchKey1-4 | String | 搜索字段（method/uri/statusCode/contentType） |
| protoFlags | int | 协议标记位 |
| connReuse | int | 连接复用标记 |

提供 getter: `method`, `uri`, `statusCode`, `contentType`，映射到 searchKey1-4。

### FlowDetail (`lib/models/flow_detail.dart`)
流量详情，包含连接信息和时序数据。

- `raw`: 完整 JSON，用于访问 metadata（headers、body 等）
- `connection`: ConnectionInfo 对象（srcIp/dstIp/srcPort/dstPort/state/tlsVersion/tlsCipher/tlsSni）
- 时序 getter: `connectAt`, `connectedAt`, `tlsDoneAt`, `reqEndAt`, `rspStartAt`

### WsMessage (`lib/models/ws_message.dart`)
WebSocket 推送消息模型。

| 字段 | 类型 | 说明 |
|------|------|------|
| type | String | 消息类型 (flow/flow_update/metrics/stats) |
| data | Map<String, dynamic> | 消息载荷 |

## 3. API 客户端

### REST API (`lib/api/api_client.dart`)
基于 `package:http` 的 REST 客户端，默认连接 `http://localhost:9090`。

| 方法 | 路径 | 说明 |
|------|------|------|
| getTasks() | GET /api/tasks | 获取所有任务列表 |
| getFlows() | GET /api/tasks/{taskId}/flows | 分页获取流量列表，支持 protocol/host/keyword/status 过滤 |
| getFlowDetail() | GET /api/tasks/{taskId}/flows/{flowId} | 获取流量详情 |
| getPayload() | GET /api/tasks/{taskId}/flows/{flowId}/{direction} | 获取请求/响应 body，支持 preview 模式 |
| getFlowStats() | GET /api/tasks/{taskId}/flows/stats | 获取流量统计（协议分布、状态分布、流量总量） |
| checkConnection() | GET /api/tasks | 检测 API 可用性（3s 超时） |
| deleteTask() | DELETE /api/tasks/{taskId} | 删除单个任务 |
| batchDeleteTasks() | POST /api/tasks/batch-delete | 批量删除任务 |

所有请求设置 10s 超时（body 类 30s）。

### WebSocket (`lib/api/ws_client.dart`)
实时推送客户端，连接 `ws://localhost:9090/ws?taskId={id}`。

**特性**:
- 三种状态: `disconnected` / `connecting` / `connected`
- **自动重连**: 指数退避策略（1s, 2s, 4s, 8s ... 最大 30s）
- 断开后自动重连，重连成功后触发 FlowController 重新加载首页数据
- 支持 `switchTask()` 切换任务（断开旧连接 + 重新连接）
- 消息流和状态流均为 broadcast stream

## 4. GetX Controllers

应用采用 GetX 作为状态管理框架。所有 Controller 在 `main()` 中通过 `Get.put()` 全局注册。

### TaskController
- 管理任务列表 (`tasks`) 和当前任务 (`currentTask`)
- `loadTasks()`: 启动时加载任务列表
- `selectTask()`: 切换任务时联动 FlowController、LiveController、DetailController

### FlowController
- 管理流量列表 (`flows`)、选中流量 (`selectedFlow`)、总数 (`total`)
- 支持分页加载 (`loadMore()`) 和搜索 (`search()` 带 300ms debounce)
- `addFlowFromPush()` / `updateFlowFromPush()`: 处理 WebSocket 实时推送
- 与 FilterController 联动，变更筛选条件时 `reloadFromFirstPage()`

### LiveController
- 桥接 WebSocket 消息与各 Controller
- 处理四种消息类型:
  - `flow`: 新流量 → FlowController.addFlowFromPush + DashboardController.addTrafficPoint
  - `flow_update`: 流量更新 → FlowController.updateFlowFromPush
  - `metrics`: 系统指标 → 更新 memoryMB / connectionCount / DashboardController
  - `stats`: 汇总统计 → 更新 uploadBytes / downloadBytes
- 状态栏指标: requestCount / uploadBytes / downloadBytes / memoryMB / connectionCount

### TreeController
- 自动根据 FlowController.flows 构建域名树 (`ever` 监听)
- 域名分组、排序（置顶域名优先，按请求数降序）
- 支持域名选择筛选和置顶(pin)功能

### DetailController
- 加载流量详情 (`loadDetail`) 和请求/响应 body (`loadBodies`)
- 管理 7 个 tab 的数据状态
- `clear()`: 切换任务时清空

### FilterController
- 管理三组过滤条件: 协议 / 类型 / 状态码
- toggle 式操作，支持多选
- 提供 `protocolParam` / `statusParam` 供 API 查询

### DashboardController
- 协议分布 (`protocols`)、状态分布 (`statuses`)
- 系统指标: rssMB / cpuPercent / threadCount / poolTotal / uptimeSeconds
- 流量曲线: trafficHistory（最近 60 个数据点）
- `loadStats()`: 从 REST API 加载统计数据
- `updateFromMetrics()`: 从 WebSocket metrics 更新实时指标

### HistoryController
- 历史任务列表管理
- `loadTasks()` / `isLoading` 状态

### AppPageController
- 页面路由枚举: capture / history / settings / compose / mapRemote / allowBlock / diff
- 提供各页面的 show/is 方法
- Compose 页面预填充数据管理 (`openInCompose` / `clearComposePrefill`)

### TagController
- 流量颜色标记 (`_tags: flowId → Color`)
- 流量备注 (`_comments: flowId → String`)
- 6 种预定义标记颜色: Red / Orange / Yellow / Green / Blue / Purple

### ToolsController
- Map Remote 规则管理 (`mapRemoteRules`)
- Allow/Block 列表管理 (`allowList` / `blockList`)
- No Caching 开关 (`noCachingEnabled`)
- MapRemoteRule 数据结构: matchPattern + replaceScheme/Host/Port/Path + enabled

## 用户操作流程

1. 启动应用 → Flutter 引擎初始化，注册所有 GetX Controller
2. 首帧回调 → TaskController.loadTasks() 加载任务列表
3. 自动选择第一个任务 → FlowController.setTaskId() + LiveController.connectToTask()
4. WebSocket 连接建立 → 实时接收新流量和系统指标
5. 用户在 GlobalBar 切换页面（Capture / History / Settings / Compose / Tools）

## 边界条件与异常处理

- API 不可用时：静默 catch，由 ConnectionIndicator 显示断开状态
- WebSocket 断线：自动指数退避重连，重连成功后刷新流量列表
- 所有 REST 请求带超时（10-30s），防止 UI 卡死
- 空任务列表：currentTask 为 null，不加载流量

## Proxyman 参考

### 功能对标

Proxyman 的整体应用架构和基础设施。Proxyman 是一款 macOS 原生应用（Swift + AppKit），采用经典的三栏布局设计，内置代理引擎、SSL 解密和丰富的开发者工具。

### Proxyman 界面布局描述

Proxyman 主界面采用经典的三栏布局：
- **左侧 Source List（约 220px）**：按域名和 App 分组的请求树形结构，支持展开/折叠。顶部有搜索框，右键域名可快速 Enable SSL Proxying。每个域名节点显示请求计数
- **中间 Flow List**：请求列表表格，列包括 Method（彩色标签）、Name（路径）、Status、Size、Time、Content-Type。支持搜索和多条件过滤。表头可点击排序
- **右侧 Flow Content**：上方请求详情，下方响应详情，可切换水平/垂直布局，也可独立窗口打开。包含 Header/Body/Cookies/Auth/Query/Raw 等多个 Tab
- **顶部工具栏**：录制按钮（红色圆点）、清除按钮、过滤器按钮、搜索框、布局切换按钮
- **底部状态栏**：显示请求数量、流量统计等信息

|------|------|
| （文字描述）Proxyman 主界面 | 左侧域名树按 App/域名分组，中间请求列表以表格形式展示 Method（彩色标签）+ Path + Status + Size + Time，右侧详情面板上下分栏显示请求和响应信息 |

### 布局优缺点分析

**优点：**
- 原生 macOS 应用，UI 响应速度极快，与系统深度集成
- 三栏布局信息密度高，专业抓包工具的标准范式
- 支持多窗口、独立详情窗口，灵活度高
- 内置代理引擎，无需额外配置即可开始抓包
- 丰富的右键菜单，操作便捷

**缺点：**
- 仅支持 macOS 和 iOS，无跨平台能力
- 付费软件，基础功能免费但高级功能需订阅
- 架构不透明，不可扩展

### Knot 与 Proxyman 差异

| 对比点 | Proxyman | Knot |
|--------|----------|------|
| 技术栈 | Swift + AppKit 原生 | Flutter + Swift NIO 混合架构 |
| UI 框架 | AppKit（原生控件） | Flutter Material3（跨平台控件） |
| 代理引擎通信 | 进程内直接调用 | localhost HTTP/WebSocket（9090 端口） |
| 状态管理 | 原生 Cocoa 绑定 | GetX 响应式框架 |
| 数据模型 | 内部私有格式 | Dart 数据类 + JSON 序列化 |
| 主题系统 | 跟随 macOS 系统 | Material3 自定义主题 + 系统跟随 |
| 跨平台 | 仅 macOS/iOS | 潜在支持 macOS/Windows/Linux |

### Knot 中尚未实现的 Proxyman 功能

- **MethodChannel/FFI 桥接**: Proxyman 原生引擎直接调用，Knot 目前通过 HTTP 中转，延迟较高
- **自动代理配置**: Proxyman 可自动配置系统代理，Knot 需要手动配置
- **App 级别流量分组**: Proxyman 可识别请求来源 App 并分组显示
- **内置 CA 证书管理**: Proxyman 提供一键安装/信任根证书的向导
- **Scripting（脚本扩展）**: Proxyman 支持 JavaScript 脚本自定义请求/响应处理
- **多窗口支持**: Proxyman 支持将详情面板独立窗口打开
